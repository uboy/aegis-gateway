# Aegis Gateway

Универсальный модульный edge-шлюз и установщик для Ubuntu 24.04, обеспечивающий защищенную маршрутизацию трафика, шифрование удаленного доступа, обратные прокси и централизованное управление сетевыми службами.

## Возможности
- **HAProxy Ingress**: Интеллектуальный L4 TLS SNI-роутер на порту 443, объединяющий все веб- и прокси-службы за единым портом.
- **Telegram Proxy (MTProto & WebProxy)**: Единый защищенный шлюз для Telegram на порту 443 (поддержка WebProxy для Desktop и Fake-TLS для мобильных клиентов без открытия дополнительных портов).
- **AmneziaWG**: Современный высокопроизводительный туннель с рандомизацией служебных заголовков и защитой от анализа метаданных (UDP/39442).
- **3x-ui Panel**: Панель управления Xray (VLESS Reality, Trojan) с изолированным доступом через SSH-туннель.
- **Dumbproxy & Caddy**: Защищенные HTTP/HTTPS прокси и реверс-прокси с маскировкой под легитимный веб-сайт.
- **OpenConnect (ocserv)**: Cisco AnyConnect совместимый SSL VPN (TCP/4443).
- **OpenVPN**: Классический VPN (UDP/1194) — режим Legacy для прямого корпоративного доступа.
- **Security Hardening**: Автоматическая настройка SSH (нестандартный порт, вход только по ключам), Fail2Ban (nftables) и закрытый фаервол UFW.
- **Safe Upgrade Pipeline**: Автоматическое безопасное обновление APT и non-APT служб (Caddy, dumbproxy) с pre-flight проверками, atomic swap и автоматическим rollback при сбое health-check.
- **Интерактивный UI**: Выбор компонентов через whiptail меню.

## Использование
1. Скачайте проект.
2. Запустите основной скрипт от имени root:
   ```bash
   sudo bash install.sh
   ```
3. Следуйте инструкциям на экране и выберите нужные компоненты в интерактивном меню.

## Архитектура Telegram Proxy (Единый порт 443)
В проекте реализована скрытная двухуровневая схема проксирования Telegram, не требующая открытия нестандартных портов наружу:
- **Внешний порт 443 (HAProxy)**: Принимает все входящие клиентские подключения.
  - Соединения с SNI прокси-домена и Fake-TLS перенаправляются на локальный бэкенд `mtproxy-tls` (`127.0.0.1:2399`).
  - Соединения Telegram Desktop (WebProxy по HTTPS/ALPN) перенаправляются в `Caddy` (`127.0.0.1:4431`), который передает веб-сокеты в `tproxy-server` (`127.0.0.1:8080`).
  - Прямые запросы без TLS Hello направляются на plain-бэкенд `mtproxy` (`127.0.0.1:2398`).
  - Любые некорректные запросы и сканеры портов получают от Caddy стандартный сайт-заглушку.
- **Внутренний RPC-бэкенд (`127.0.0.1:2398`)**: Официальный демон MTProxy, работающий на loopback-интерфейсе. Служит транспортом для связи `tproxy-server` с дата-центрами Telegram. Снаружи закрыт фаерволом.

## Поведение панели 3x-ui (важно)
- При включенном `Hardening` веб-панель **не публикуется в интернет** — это штатный и безопасный режим.
- Доступ к панели выполняется через локальный SSH-туннель:
  ```bash
  ssh -N -L 2053:127.0.0.1:2053 <user>@<server> -p <ssh_port>
  ```
- После установки панель доступна в браузере по адресу: `http://127.0.0.1:2053`.

## Примечание по Reality target/SNI
- Для маскировки Reality рекомендуется использовать домены, расположенные на распределенных международных CDN (Cloudflare, Fastly, Akamai) или крупных нейтральных сервисах, чтобы исключить риск выявления несоответствия домена и IP-адреса хостинга (SNI-IP mismatch).
- Рекомендуемые профили маскировки:
  - `dest=gateway.icloud.com:443`, `serverNames=["gateway.icloud.com"]`
  - `dest=addons.mozilla.org:443`, `serverNames=["addons.mozilla.org"]`
  - `dest=www.microsoft.com:443`, `serverNames=["www.microsoft.com"]`
- По умолчанию в конфигурации задействован flow `xtls-rprx-vision`, обеспечивающий паддинг пакетов после TLS-рукопожатия для устранения характерного размера начальных пакетов туннеля.
- В клиентских профилях подключения рекомендуется выбирать uTLS фингерпринт `chrome` или `firefox`.

## Безопасное обновление сервисов (Safe Upgrade Pipeline)
Aegis Gateway включает встроенный конвейер обновления системы и прокси-служб с предпроверками (pre-flight checks), атомарной заменой бинарников и автоматическим откатом (rollback) при сбоях:
```bash
# Проверка доступных обновлений без применения (dry-run)
sudo ./scripts/upgrade-services.sh --check

# Обновление всех компонентов (APT, Caddy, dumbproxy)
sudo ./scripts/upgrade-services.sh --all

# Обновление отдельного компонента
sudo ./scripts/upgrade-services.sh --service dumbproxy
```
Конвейер автоматически запускается еженедельно по таймеру `aegis-upgrade.timer` (воскресенье, 04:30).

## Структура проекта
- `install.sh` — главный оркестратор установки.
- `lib/` — библиотеки (API, UI, State, Utils, Upgrade).
- `modules/` — независимые модули установки конкретных сервисов.
- `scripts/` — утилиты обслуживания и оркестратор обновлений (`upgrade-services.sh`).
- `systemd/` — юниты systemd (`aegis-upgrade.service`, `aegis-upgrade.timer`).
- `docs/` — архитектурная документация и руководства.

## Системные требования
- ОС: Ubuntu 24.04 (Noble Numbat).
- Права root.
- Свободные порты для выбранных сервисов.
